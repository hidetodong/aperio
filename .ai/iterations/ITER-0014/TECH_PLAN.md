# Design Decisions

- 网页继续放在隔离框里，sandbox 保持空字符串，不授予脚本、同源和外层跳转。空属性在这台 Mac 的网页视图里能挡住脚本改外层；属性被拿掉就能改外层。
- 看网页时顶栏强制留着。探针里，带层级的按钮会画在铺满的白框上面，所以不为顶栏去改页面高度。
- 正文晚一拍写入：页面自己插入隔离框，先写 sandbox，属性仍是空字符串才写入正文。大页面第一次写进去时画不出来，大约 800 毫秒后再按同样的正文写一次。写不进去就卸掉框。窗口拉大后不再重算框的像素，后写尺寸会把大页面冲成空白。
- 放弃把网页洗干净后直接画进外层。不隔离时脚本能改外层，洗标签也解决不了顶栏被白框盖住的观感问题。
- 放弃让脚本在隔离框里运行。脚本和阅读器在同一个网页视图里，跑起来会把窗口拖死。
- 放弃交给别的程序打开。这一版不做「用其他应用打开」。
- 白底或脚本没画出来，仍显示隔离框，不改成失败提示。

# Plan Admission

- AC Coverage：AC1 由阅读框在网页种类上强制显示顶栏，测试看标记和返回按钮。AC2 由隔离框的延迟写入和失败提示覆盖，测试看空 sandbox、正文，以及属性被丢时的提示。AC3 由现有阅读框测试覆盖，网页和 Markdown 的按钮文案、Markdown 收起顶栏。AC4 由现有打开测试覆盖，失败原因是那句 2MB 提示，结果不是网页正文。
- Assumptions：这台 Mac 的网页视图会遵守空的 sandbox。探针已看到脚本被挡住。若以后视图不遵守，属性检查发现不了，这是剩余风险，不是当前能在脚本里补上的洞。React 若把空 sandbox 丢掉，延迟写入会走到提示，不把正文放进去。
- Alternatives / Trade-offs：采用隔离框加顶栏不收。放弃洗进外层、放弃跑脚本、放弃交给别的程序、放弃为顶栏缩页面。缩页面会改已经能看的网页边距，探针又说明按钮画得出来，所以不缩。
- Failure Modes：sandbox 写不进去时卸框并提示。读入被拒绝时沿用失败结果，阅读区不是隔离框。同一框换正文时，失败标记绑在上一份正文上，新正文会重新检查。Markdown 顶栏仍按自动隐藏收起，用现有测试挡住误伤。
- Impact / Scope Challenge：只动隔离框、一句文案、一条只作用于网页的样式，以及已有的顶栏条件。不改打开文件的尺寸判断，不改其他格式。样式表原先打算不动。网页宿主没有高度时隔离框是一块空白，所以补上铺满阅读区这一条。更小的做法是只留顶栏，但确认过的失败提示就没有落点，所以保留延迟写入。
- Verification Blind Spots：单元测试不跑页内脚本，也不点真窗口。合成点击进不了当前这个阅读器窗口。顶栏能点，靠「收起样式没有套上」和网页视图探针里按钮像素还在来支撑，真机点击若环境不允许就如实记成没点到。
- Verdict：pass。没有必须先改方案才能写的问题。真窗口点击是验证盲区，不是方案缺陷。样式表补一条、以及大约 800 毫秒后再写一次正文，是实现里坐实的必要偏差，2026-10-28 复核后结论仍是 pass。
