# AC_LIST — ITER-0003

> ⚠️ 危险模式：本产物由模型自主 ACK（已过 §5 自审门），未经用户确认（ITER-0003，2026-09-29）

## Goal

- 在自己的 Mac 上打开一份 PDF，能顺着翻页，并且只有看得到的页被画出来。

## In Scope

- 启用名单打开 pdf，图片和文本仍开着
- 查看器单独一块，按需加载，主包里没有它
- 只绘制当前视口里的页，离开视口的页不再占着画面
- 换文件或关闭时丢掉上一份 PDF
- 打不开时显示原因，不写入最近列表
- Rust 依赖里仍然没有 PDF 解析库

## Out of Scope

- 编辑、批注、填表、导出
- 密码输入和光学识别
- 文字选择
- Office、压缩包、影音
- 像素级还原版面
- 真窗口里的滚动手感不作为这一段的自动通过线

## Acceptance Checklist

- [x] AC1: 启用名单里 pdf 开着，图片和文本仍开着，Office、压缩包、影音关着。只有开着的 pdf 才有加载函数。
- [x] AC2: 构建之后，PDF 查看器在主包以外的单独一块里。主包里没有 PDF 查看器标记，也没有 pdf.js。Rust 依赖里没有 PDF 解析库，仓库根下没有另拷的字体文件。
- [x] AC3: 一份多页 PDF 打开后，只绘制视口里的页。视口外的页不绘制。滚走之后，已经离开视口的页不再留着画布。
- [x] AC4: 文件不在、内容不是 PDF，或 PDF 打不开时，画面显示原因，最近列表不追加，上一份内容不留。
- [x] AC5: 换走这份 PDF 时，上一份文档被释放。同一时间不留两份 PDF 文档。

## Verification Method

- AC1: 单测读启用名单和加载函数。关掉的格式没有加载函数。
- AC2: 构建后跑分包检查。依赖和字体边界检查确认 Rust 侧没有 PDF 解析库，仓库里没有另拷的字体。
- AC3: 用假的文档对象做组件测试。五页的文档在只看得到第一页时，只绘制第一页。把视口移到最后一页后，第一页的画布不再留着，最后一页被绘制。
- AC4: 单测让确认文件或解析直接失败，断言画面是原因原文，最近列表不变，上一份不在状态里。
- AC5: 单测在换文件时断言上一份文档的释放函数被调用，新的一份还在。
