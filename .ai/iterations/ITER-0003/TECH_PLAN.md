## Design Decisions

- 目标只支撑 AC1 到 AC5。不打开 Office、压缩包和影音。
- 用 pdf.js 在前端画页面。文件字节由页面通过已经允许的本地资源地址去取，不在 Rust 里新增读全文件或解析 PDF 的命令。被放弃的做法是在 Rust 里加解析库，因为格式解析约定留在前端。
- 查看器做成单独一块，用到才加载。启用名单把 pdf 打开。分包检查从「构建产物里不许出现 PDF」改成「主包里不许出现，单独一块里必须出现」。依赖检查仍禁止 Rust 侧出现 PDF 解析库，但允许前端依赖里出现 pdf.js。
- 页的位置先按估算高度排开，只给视口里的页建画布。离开视口的画布拆掉。被放弃的做法是一次把每一页都画出来，长文档会把内存吃掉。
- 文档对象在换文件或离开画面时释放。打开流程仍只采纳最后一次。
- 解析失败、文件不在、加密打不开，都走现有的错误画面，不新增密码框。被放弃的做法是做密码输入，这一段不需要。
- 不铺文字选择层。被放弃的做法是用 pdf.js 的文字层，那会把看得到的页再铺一份文字。
- 不把字体文件拷进仓库。PDF 自己嵌的字体用它的。缺标准字体时允许替代。
- 若后台线程加载失败，就在同一线程里解析，而不是把整份文件打成打不开。这只影响快慢，不改变画哪些页。

### 文件与模块

- `src/formats/enable.ts`：打开 pdf。
- `src/formats/load.ts`：pdf 查看器按需加载。
- `src/formats/pdf/`：页面视图和「只画看得到的页」。
- `src/open/openFile.ts`：PDF 成功时交出文档所需的地址，失败走现有错误结果。
- `scripts/check-chunks.mjs`：主包与 PDF 块分开。
- `scripts/check-boundaries.mjs`：允许前端依赖 pdf.js，继续禁止 Rust 解析 PDF，继续禁止仓库里另拷字体。

### 接口

- 打开结果增加一种 PDF 当前内容，只带路径、名字和本地地址。文档对象由查看器自己创建和释放。
- 假的文档对象供测试使用，测试不加载真的 pdf.js。

### 边界

- Rust 依赖不增加 PDF 库。
- 不改图片和文本的查看方式。
- 浏览器拖放若拿不到本机路径，PDF 仍按上一段的浏览器限制处理，不新造一条读盘路径。

### Plan Admission

- AC Coverage：AC1 到 AC5 都有单测或构建后检查，不靠口头说明。
- Assumptions：pdf.js 能在系统网页视图里把一页画到画布上。后台线程若加载失败，可以退到同一线程。这个假设若在实现时不成立，就退回改方案，不用「画全部页」绕过去。
- Alternatives / Trade-offs：见上面被放弃的做法。没有把 Office 并进来，也没有重开上一段。
- Failure Modes：文件不在、内容不是 PDF、加密、后台线程失败、页数很多。前三个走错误画面且不记最近列表。后台线程失败则同一线程继续。页数很多时仍然只画视口里的页。
- Impact / Scope Challenge：改动停在启用名单、打开结果、PDF 查看器和两条检查脚本。更小的做法是把所有页一次画完，但那就达不到「只排看得见的页」。
- Verification Blind Spots：单测用假文档，不能证明真窗口里翻页顺手，也不能证明每一种字体都好看。这两件不写成自动通过线。
- Verdict：pass。没有必须先改方案才能写的问题。

## Failure Paths

- 文件不在：显示找不到，不进最近列表，画面不留上一份。
- 内容不是 PDF，或加密打不开：显示解析给出的原因。不弹密码框。
- 后台线程加载失败：改在同一线程打开。仍然只画看得到的页。
- 页数很多：视口外的页不建画布。
- 换文件：上一份文档释放。

## Test Strategy

- 前端单测覆盖启用名单、失败结果、假文档的视口绘制和释放。
- 构建后跑分包检查和依赖边界检查。
- 不把真窗口里的翻页手感写成通过条件。
