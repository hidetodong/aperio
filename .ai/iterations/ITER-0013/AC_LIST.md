# AC_LIST — ITER-0013

## Goal

- 已经按纯文本打开的文件，打开后用阅读字体和段落间隔，读起来有层次。代码仍按现有语言上色。看到的文字和文件内容一致。

## In Scope

- 纯文本改成阅读排版：使用界面已有的无衬线字体，字号走阅读字号，长行换行。原文里用空行隔开的两段，段与段之间有额外空隙，空隙跟文章段落现在的空隙同一档。
- 显示出来的段落文字和原文对应段落一致，不自动缩进，不增删段落里的字符。
- 现有代码名单保持按语言上色，并保留行号。名单不增不减。
- Markdown 默认仍是文章。网页默认仍是不允许脚本的隔离框。两边现有的原文切换还在。
- 专注模式仍换纯文本的底色，纯文本的字号仍走阅读字号。

## Out of Scope

- 不改磁盘上的文件。
- 不加新语言，不换上色库，不重调代码颜色。
- 不重做 Markdown 的标题、表格和图片。
- 不改网页隔离框里的页面样式，也不处理网页把整窗打挂。
- 不改图片、PDF、Office、压缩包列表和影音的打开方式。
- 不扩大能打开的种类，不改扩展名归类。
- 不把「暂不支持的文件格式」和网页的「渲染 / 原文」补进这轮验收。
- 纯文本不加「阅读 / 原文」切换。

## Acceptance Checklist

- [ ] AC1: 纯文本使用界面已有的无衬线字体，不用等宽字体。字号使用阅读字号，长行会换行。原文用一个空行隔开的两段，段与段之间有额外空隙，这档空隙和文章段落现在的空隙相同。
- [ ] AC2: 上面这两段显示出来的文字，和原文对应段落一致。不出现自动补上的缩进、标题或符号。
- [ ] AC3: 现有代码扩展名打开后仍按语言上色，并显示行号。以 TypeScript 为例，关键字上色，每一行有行号。语言名单仍是 js、jsx、mjs、cjs、ts、tsx、json、py、go、rs、sql、yml、yaml、css、sh、bash、zsh。
- [ ] AC4: Markdown 默认仍渲染成带标题的文章。网页默认仍是不允许脚本的隔离框。Markdown 的切换文案仍是「阅读 / 原文」，网页的切换文案仍是「渲染 / 原文」。纯文本没有这两套切换。
- [ ] AC5: 扩展名归类保持现状。txt 仍是纯文本，ts 仍是代码，md 仍是 Markdown，html 仍是网页。pdf、png、docx、zip、mp4 仍是各自原来的家族。认不出的扩展名（例如 log）家族仍是 unknown，文本模式仍是纯文本。
- [ ] AC6: 专注模式打开时，纯文本区域仍改用专注底色，字号仍跟随阅读字号，不写死成代码区的字号。

## Verification Method

- AC1: 渲染一份带空行的纯文本，核对字体、换行和段间距。段间距对照文章段落现在的空隙。样式规则能在样式表里读到。
- AC2: 同一份渲染结果里，两段的文字与传入原文一致。
- AC3: 渲染一份 TypeScript，核对行号和关键字上色。路由测试核对语言名单没有增减。
- AC4: 沿用现有 Markdown 和网页渲染测试，核对默认文章、隔离框和两套切换文案。纯文本渲染结果里没有这两套按钮。
- AC5: 路由测试核对 txt、ts、md、html、pdf、png、docx、zip、mp4 和 log 的家族与文本模式。
- AC6: 读取样式表里专注模式对纯文本的底色规则，以及纯文本字号使用阅读字号变量。

这些验收都来自通用流程。配置里没有启用专项规则，所以没有专项验收项。没有外部参考资料。
