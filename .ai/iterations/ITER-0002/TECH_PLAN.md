## Design Decisions

- 目标只支撑 AC1 到 AC6。不改启用名单，不开始 PDF。
- 失败文案从三种值里取：非空字符串用原文，Error 用它的 message，其余才写「打不开」。被放弃的做法是只认 Error，因为本机命令失败传回来的就是字符串。
- 图片在生成地址之前先让 Rust 确认这是一个还在的文件。文本本来就会在读取时确认，不重复做一次。被放弃的做法是在页面里用资源地址探测，失败时已经来不及阻止最近列表。
- 打开流程不再用开始时的最近列表快照。成功时把这一条叠到提交那一刻的列表上。用一个递增号码只采纳最后一次。列表没读完就先排队，读失败则只更新画面、不写磁盘。
- HEIC 解码只负责写出一张新的 png，不在命令里删除其他文件。页面确认这次结果仍是最后一次之后，才调用清理。清理先核对路径在应用缓存目录内且是 png。被放弃的做法是解码一结束就删掉其他 png，因为后返回的旧解码会把正在显示的图删掉。
- sips 的程序路径写成 `/usr/bin/sips`。参数维持数组。
- Markdown 在文章上拦住指向链接的点击，不新开窗口，也不跟随。被放弃的做法是改消毒策略去拆掉链接，因为链接文字本身还可以留着看。

### 文件与模块

- `src/open/`：失败文案、打开结果、排队门、最近列表叠加上去的纯函数。
- `src/App.tsx`：只采纳最后一次，列表读完再放行。
- `src/bridge.ts`：增加确认文件和清理缓存两个调用。
- `src/formats/text/TextView.tsx`：拦住链接点击。
- `src-tauri/src/files.rs`：确认文件，sips 固定路径。
- `src-tauri/src/lib.rs`：解码不再清理；另给一个只清缓存目录的命令。

### 接口

- 确认文件成功不返回内容。失败原因沿用现在的「找不到这个文件」和「这不是文件」。
- 打开结果只带当前内容。最近列表由提交时的状态另算。HEIC 成功时可以带一个清理动作，调用方决定要不要执行。
- 清理命令只接受应用缓存目录里的 png 路径。

### 边界

- Rust 仍不解析 PDF 或 Office。
- 不改图片和文本的按需加载。
- 浏览器拖放没有本机路径，不调用确认文件。

### Plan Admission

- AC Coverage：AC1 到 AC6 都有对应的纯函数或 Rust 测试，不靠口头说明。
- Assumptions：本机命令失败时拒绝值是字符串。这个假设用直接拒绝字符串的单测钉住，不依赖真窗口才能发现。
- Alternatives / Trade-offs：见上面每条被放弃的做法。没有把修复并进 PDF，也没有重开上一段。
- Failure Modes：确认失败、读失败、解码失败、清理路径不在缓存目录、列表读失败、旧打开后返回。前几个走错误画面且不记最近列表。清理路径不对就拒绝且不删文件。列表读失败则不写磁盘。旧打开后返回则整次丢弃。
- Impact / Scope Challenge：改动停在打开流程、HEIC 缓存和 Markdown 点击。不改格式名单，不改归档。更小的做法是只修字符串文案，但缺文件和竞态仍会让验收在真窗口里不成立，所以三处一起修。sips 路径和链接点击是同一审查里指出的，顺手修，不另开范围。
- Verification Blind Spots：单测覆盖不到真窗口里人手点两次那么快的体感。排队门和号码的单测是代理，不当成已经在真窗口里点过。HEIC 仍不在窗口里再打开一次。
- Verdict：pass。没有必须先改方案才能写的问题。

## Failure Paths

- 文件不在：显示找不到，不进最近列表，画面不留上一份。
- 路径是目录：显示不是文件。
- 文本过大或不是文本：显示原来的那句原因。
- sips 不存在或解码失败：显示原来的失败原因。
- 清理路径不在缓存目录：拒绝，不删除。
- 最近列表读取失败：画面仍可打开，但不把内存里的列表写回磁盘。
- 旧打开后返回：不改画面，不改列表，不清理缓存。

## Test Strategy

- 前端单测覆盖字符串拒绝、缺图片、排队门、最近列表叠加、链接点击。
- Rust 单测覆盖缓存清理的范围，以及 sips 路径。原有的读文本和 HEIC 样例测试继续跑。
- 不把 80MB 和 1 秒启动写成这一段的通过条件。
