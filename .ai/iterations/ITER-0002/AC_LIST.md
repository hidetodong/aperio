## Goal

- 真窗口里的打开结果要和已经冻结的验收一致：失败说原本的原因，缺了的文件不要装成成功，后返回的旧打开不能盖掉新文件。

## In Scope

- 本机命令用字符串拒绝时，界面显示这段原文
- 普通图片打开前先确认文件还在
- 只提交最后一次打开，最近列表没读完时不把空表写回磁盘
- 只有真正显示的 HEIC 缓存图才清理同目录其他 png，并且路径必须在应用缓存目录里
- 解码程序固定为 `/usr/bin/sips`
- Markdown 链接点击不把当前窗口导航走

## Acceptance Checklist

- [ ] AC1: 读文本或解码失败时，如果拒绝值是一段非空字符串，界面显示这段原文，而不是「打不开」。最近列表不追加。上一份内容不留在画面上。
- [ ] AC2: 打开 jpg、jpeg、png、gif、webp、svg 之前先确认这是一个还在的文件。文件不在或是目录时，显示对应原因，清掉上一份，不写入最近列表。
- [ ] AC3: 连续打开时只留下最后一次的画面和最近列表。更早的那次即使后返回，也不改这两者。最近列表还没从磁盘读完时，打开动作先排队，不用空列表覆盖磁盘。
- [ ] AC4: 过期的 HEIC 解码不删除当前要显示的缓存图。清理只发生在这次结果被采纳之后，并且只删除应用缓存目录里、除了保留文件以外的 png。缓存目录以外的路径直接拒绝，不删文件。
- [ ] AC5: HEIC 解码调用的程序是 `/usr/bin/sips`，参数仍是数组，不经过外壳拼接。
- [ ] AC6: Markdown 里的普通链接被点击时，当前窗口不因此跳走。

## Verification Method

- AC1: 单测让读文本直接拒绝一个字符串，断言画面文案就是这串字，最近列表不变，上一份正文不在状态里。
- AC2: 单测让确认文件拒绝字符串「找不到这个文件」和「这不是文件」，断言不记入最近列表，上一份被清掉。确认函数在图片分支被调用，在关掉的格式上不被调用。
- AC3: 单测覆盖排队门。未读完时两次打开都进队列且不允许写盘；读完后按原顺序放出。后开始的那次才算当前，先开始的返回时被丢掉。成功打开时最近列表叠在当前状态上，不使用打开开始时的快照。
- AC4: Rust 单测在临时目录放两张 png，采纳其中一张后另一张消失。目录外的 png 被拒绝，文件还在。前端只在这次打开仍是最后一次时才调用清理。
- AC5: Rust 单测断言程序路径就是 `/usr/bin/sips`，并且这台机器上该文件存在。现有的系统 HEIC 样例仍能解出 PNG。
- AC6: 组件测试渲染带链接的 Markdown，点击链接，断言这次点击被拦住。
