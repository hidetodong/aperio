## Goal

- 只支撑 AC1 到 AC5：ZIP 名单和包内预览，加上 MP4、MOV、MP3 的系统播放。

## Design Decisions

- 压缩包用已经在依赖里的 JSZip 读名单和单个条目。影音只把地址交给页面里的视频或音频标签，不把整份读成文本。被放弃的做法是在 Rust 里加压缩或影音库，因为格式解析约定留在前端，影音又本来就交给系统。
- 查看器分成两块，用到才加载。打开压缩包时不顺带把影音放进主包。启用名单把 zip 和 media 打开，原来开着的四个家族不动。
- 压缩包字节仍由页面通过已经允许的地址去取，不新增 Rust 读全文件的命令。浏览器里先看文件大小，超过 20MB 不交给解析。本机路径仍是先确认文件，取到字节后再按大小拒绝。
- 包里预览只取被点到的那一项。文本、图片、PDF 交给现有查看器。压缩包读取代码不引用这些查看器。Office、另一个 ZIP、影音、HEIC 只留在名单里，点了就说明这一段不预览。
- 名单超过 2000 项就停，并写明后面还有。单个条目在取出来之前先看未压缩大小，超过 20MB 就不取。被放弃的做法是把包里所有文件一次解出来。
- 有密码时把库的报错说成先不看。不增加密码输入框。
- tar、gz、tgz 在打开时直接说明，不读内容。被放弃的做法是把它们当未知文件读成文本。
- 成功的压缩包和影音进入最近列表，但都要等画面侧确认：名单出现，或播放标签报告能播。失败不进。PDF 仍保持成功不进最近列表。
- 换文件时丢掉上一份名单、包内临时地址和播放。晚到的成功或失败不能盖住下一份。
- 系统窗口要播本地影音，内容安全策略要允许影音来自本机资源地址和临时地址。不放宽脚本来源。

### 文件与模块

- `src/formats/enable.ts`：打开 zip 和 media。
- `src/formats/load.ts`：这两个查看器按需加载。
- `src/formats/route.ts`：认出 tar、gz、tgz，避免落到文本。
- `src/formats/zip/`：名单、单条目预览、画面。
- `src/formats/media/`：视频和音频画面。
- `src/messages.ts`：先不看、太大、有密码、不是压缩包。
- `src/open/openFile.ts`：压缩包和影音只交地址。tar 和 gz 直接说明。
- `src/open/session.ts`：当前内容可以是压缩包或影音。最近列表要等画面确认。
- `src/App.tsx`：接上两块画面。浏览器拖进来时，压缩包先看大小，影音不读成文本。
- `src/App.css`：名单和播放的版面。
- `src-tauri/tauri.conf.json`：影音地址允许本机资源和临时地址。
- `scripts/check-chunks.mjs`：主包里不许出现这两个查看器标记。
- `scripts/check-boundaries.mjs`：继续禁止 Rust 解析格式，并禁止压缩包读取代码去引 PDF。

### 接口

- 打开结果增加压缩包和影音两种当前内容，只带路径、名字和地址。名单和包内预览由压缩包画面自己持有。
- 读取函数接受字节，测试不依赖真窗口。条目预览返回文本、图片字节、PDF 字节，或者一句说明。

### 边界

- Rust 依赖不增加压缩或影音库。
- 不改 PDF 只画看得到的页，也不改 PDF 不进最近列表。
- 不改 Office 的解析和「正文出现才进最近列表」。
- 不改图片和文本原来的打开方式。包内预览只是复用它们。

## Plan Admission

- AC Coverage：AC1 到 AC5 都有单测或构建后检查。真窗口观感不在自动通过线里。
- Assumptions：JSZip 能列出普通 ZIP 的名字，并取出其中一项的字节。有密码的包会带着 encrypted 这个词失败。条目的未压缩大小能在取出之前读到。这个大小若读不到，就在取出后按字节数拒绝，并且不把它交给查看器。以上假设若实现时不成立，就退回改方案，不许把压缩包或 tar 当成纯文本打开。
- Alternatives / Trade-offs：见上面被放弃的做法。没有把包里的 Office 并进来，也没有重开 PDF 或 Office 那两段。
- Failure Modes：文件不在、内容不是压缩包、有密码、超过 20MB、条目超过 20MB、包里的格式这一段不预览、影音播不了、晚到的结果。前几个走错误或说明，不进最近列表。条目太大或格式不预览时，名单仍然算打开成功。
- Impact / Scope Challenge：改动停在启用名单、打开结果、两块新画面、内容安全策略里的影音来源，以及两条检查脚本。更小的做法是只做名单、不预览包内文件，但路线写的是名单和包内预览，再加上影音。
- Verification Blind Spots：单测里的影音只证明播放标签发出了能播或失败。不能证明真窗口里声音和画面顺。压缩包炸弹如果把未压缩大小藏起来，取出后才会被拒绝。这两件不写成自动通过线。
- Verdict：pass。没有必须先改方案才能写的问题。

## Failure Paths

- 文件不在：显示找不到，不进最近列表，画面不留上一份。
- tar、gz、tgz：显示先不看，不读内容。
- 内容不是压缩包：显示这不是压缩包。
- 有密码：显示先不看，不弹密码框。
- 超过 20MB：显示太大，不解析。
- 某一项超过 20MB，或这一段不预览：名单还在，这一项旁边或下方说明原因。
- 影音播不了：显示播不了，不进最近列表。
- 换文件，或晚到的结果：不盖住下一份，也不追加错的最近列表。

## Test Strategy

- 前端单测覆盖启用名单、tar 和 gz、失败结果、最近列表、最小 ZIP、超限和密码文案、播放标签的能播和失败。
- 构建后跑分包检查和依赖边界检查。
- 不把真窗口里的观感写成通过条件。

## Verification Plan

- T1 到 T4 做完后跑前端测试、构建、分包检查和依赖边界检查。
- 浏览器里用一份最小 ZIP 和一个很小的影音文件看一眼名单和播放标签。真窗口不作为通过线。

## Risks / Open Questions

- 真窗口没点之前，不能说系统窗口里已经能播。
- 内容安全策略改完，要重启应用窗口才生效。只刷新页面不够。
- 未压缩大小若只能在取出之后看到，内存可能先涨一下。这种条目仍然不能交给查看器。
