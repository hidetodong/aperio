# MILE-0001 浮现个人阅读器第一版

## 范围评估

### In Scope（版本级）

本版只做一件事：在自己的 Mac 上，用一个轻窗口看常见文件。

窗口：

- 一个窗口，能拖文件进去，也能记住最近打开的文件

文档：

- PDF，翻页要顺
- Word（.docx）、Excel（.xlsx）、PPT（.pptx）、CSV：只看内容。不编辑。PPT 不追动画，也不追和 Office 一样的版面

文本：

- Markdown、TXT、HTML，以及任意纯文本都能打开
- 代码高亮只做这些：JavaScript、TypeScript、JSON、Python、Go、Rust、SQL、YAML、CSS、Shell

图片：

- JPG、PNG、GIF、WebP、SVG、HEIC

影音：

- MP4、MOV、MP3，走系统播放

压缩包：

- ZIP 先列出里面有什么。包里的 PDF、图片、文本可以预览

加载方式：

- 格式按家族拆开，用到才加载
- 有一份启用名单。名单里关掉的格式，就等于不支持
- 不做给别人安装的插件市场，也不做插件之间的隔离

### Out of Scope（版本级）

- 相机原始图、PSD、TIFF、旧的 .doc 和 .xls、EPUB、思维导图、三维、CAD、SketchUp、TAR 和 GZ
- 把代码高亮做成几十种语言
- 在里面改 Word、Excel、PPT，或做飞书那种一块一块的 Markdown 编辑器
- 公证、收款、试用锁、海外支付、自动更新、Windows、网站
- 给本地代理用的命令行桥
- 把 Chrome 打进安装包，或自己带一套中文字体

### 关键交付目标

- 自己在 Mac 上拖一个名单内的文件进去，就能看到内容
- 冷启动到窗口能接拖放，控制在 1 秒内。第一次打开 PDF 或 Word 允许更慢，因为那一块是打开时才加载
- 空闲内存按不超过 80MB 来要求。系统网页视图本身要占几十 MB，这是下限，不拿它跟纯原生程序比
- 没在用的格式解析不进启动。关掉的格式就是不支持
- 内存里只留当前这一份文件。PDF 只排看得见的页

## 理解阐释

### 核心问题

想要一个自己用的窗口：文件拖进去，内容才浮出来。不要为每种格式各开一个应用，也不要做成什么格式都塞进去的大阅读器。

第一版压三件事：占内存小，启动快，格式按需加载。

### 背景与价值

对照过 Omia（xiaoeromia.com，小耳做的本地多格式阅读器）。它证明这条路走得通：桌面壳加系统网页视图，格式在前端里看。它的安装包大，大头是中文字体。格式数量里有不少只是代码高亮的语言名。Office 编辑、飞书式块编辑、支付、公证、自动更新，都是它后面才堆上去的，这一版全部不做。

给人看的名字是「浮现」，英文 Emerge，工程目录是 emerge。涌现是“部分里没有、合在一起才出现”的那个理论词，太大，也容易和现成说法撞车。浮现说的是窗口里内容变得看得清的那一下。不用 Emergence，也不用 Surface，后者是微软的产品名。

范围按一个人、大约两到四周来估。这个数是规划，不是验收线。插件如果只是懒加载模块加启用名单，就含在这两到四周里，不单独立项做平台。

### 对系统的整体影响

仓库现在是空的，第一版等于从零起一套程序，不改任何既有模块。

壳用 Tauri 2，也就是用 Rust 包一层 Mac 自带的网页视图，不把 Chrome 打进去。Rust 只做三件事：打开文件、读字节、用系统能力解 HEIC。苹果手机默认就是 HEIC，Mac 上用系统解码比较便宜。格式解析不写在 Rust 里。

界面用 TypeScript，React 画界面，Vite 打包。格式模块用动态导入，一个格式家族打成一块，启动时不进主包。

各家族打算用的库：

- PDF 用 pdf.js
- Word 和 PPT 用 JSZip 解开，再自己读里面的 XML，只取能看的内容
- Excel 用 SheetJS。CSV 手写解析
- Markdown 用轻量渲染，加上 highlight.js，只带上面点名的语言
- 图片交给浏览器自己显示。HEIC 走 Mac 系统解码
- 影音用页面里的视频和音频标签
- ZIP 用 JSZip

字体用系统的，不打包中文字体。同一时间只解析当前这份文件。

技术画像先空着。等源码出现，再考虑打开 TypeScript 那套检查，不在空仓库上提前开。
