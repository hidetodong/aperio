# MILE-0002 开源仓库与 v0.0.1 发布准备

## 范围评估

### In Scope（版本级）

这一版只做发布准备，不改查看器本身。三件事：

- 仓库根的 README 按开源项目来写：这是什么、给谁用、能打开哪些文件、在 Mac 上怎么跑、怎么构建、许可证在哪、不做什么。
- 把仓库传到 GitHub，并配好 GitHub Actions。检查要能自动跑，并打出 Mac 安装包。
- 把现有工程补到能发 v0.0.1：版本号对齐、补上许可证、发版前要过的检查收成一条说得清的入口。

### Out of Scope（版本级）

- 公证、自动更新、网站、Windows、收费、插件市场。
- 改能看的格式，或再改界面。
- 把个人使用的阅读器改成要卖的商业版。
- 这一版不包含已经发给别人。包和标签准备好为止。是否自动发 GitHub Release，见下面的待澄清。

### 关键交付目标

- 仓库根有 README。外人能照着在 Mac 上把 Aperio 跑起来，并知道它不做什么。
- GitHub 上有这个仓库。Actions 在推送或打版本标签时跑检查，并产出 Mac 安装包。
- 准备发布的版本号是 v0.0.1。`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 三处一致。发版前的检查有一条命令或一份说明。

## 理解阐释

Aperio 现在只在本机开发。仓库根没有 README，没有 GitHub 远程，也没有自动打包。想按开源项目的样子把 v0.0.1 准备好，缺的就是这三块。

显示名是 Aperio。npm 包和 Rust 库仍叫 emerge，包标识是 `local.aperio.app`。只做 Mac。以前的迭代写明不对外分发。这一版要的是仓库说明和自动化打包达到开源项目的底线，不是改产品去卖。

主要动仓库根的说明、许可证、版本号，以及 GitHub Actions。查看器的界面和格式名单不动。打包沿用现有的 Tauri 构建。现在这三处版本号都写着 0.1.0，和要发的 v0.0.1 不一致。怎么对齐等开工时定，这里不猜。

仓库现在没有 GitHub 远程，也没有 `.github` 工作流。Actions 要等仓库能推上去之后才接得上。

### 待澄清

- GitHub 用哪个账号或组织，仓库名用 Aperio 还是 aperio，公开还是私有。README 按开源项目写，通常是公开仓库，但这点还没说死。
- 许可证用哪一种。仓库里现在没有 LICENSE。
- v0.0.1 是把现有的 0.1.0 改成 0.0.1，还是把要发的版本改口成已经写着的 0.1.0。
- Actions 打出的 Mac 包只放在构建产物里，还是同时发 GitHub Release。
