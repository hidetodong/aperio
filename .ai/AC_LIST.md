# AC_LIST — ITER-0005

> ⚠️ 危险模式：本产物由模型自主 ACK（已过 §5 自审门），未经用户确认（ITER-0005，2026-09-29）

## Goal

- 在自己的 Mac 上打开 ZIP，能看到里面的名字，并预览其中的 PDF、图片和文本。MP4、MOV、MP3 交给系统播放。

## In Scope

- 启用名单打开 zip 和 media。图片、文本、PDF、Office 仍开着
- 查看器按需加载。压缩包和影音都不在主包里
- 最小 ZIP 列出名字。包内文本能看到正文。包内图片和 PDF 交给现有查看器，压缩包自己不解析它们
- tar、gz、tgz 说明先不看，不去当文本读
- 压缩包超过 20MB 不整份解析。打不开时说明原因，不进最近列表，上一份正文不留
- 名单出现之后，压缩包才进最近列表。影音要等能播才进。失败不进
- 换文件后，上一份名单或播放不留
- PDF 成功打开仍然不进最近列表
- Rust 依赖里仍然没有压缩或影音解析库

## Out of Scope

- 编辑压缩包、解到磁盘、密码框
- 包里的 Office、嵌套压缩包、影音和 HEIC
- tar 和 gz 的真实内容
- 改 PDF 成功不进最近列表
- 改已经收口的 Office 解析
- 真窗口里的观感不作为这一段的自动通过线

## Acceptance Checklist

- [ ] AC1: 启用名单里 zip 和 media 开着，图片、文本、PDF、Office 仍开着。只有开着的家族才有加载函数。
- [ ] AC2: 构建之后，压缩包查看器和影音查看器都在主包以外。主包里没有这两个查看器标记，也没有 JSZip。Rust 依赖里没有压缩或影音解析库。压缩包的读取代码不引用 PDF 或图片解码。
- [ ] AC3: 一份最小 ZIP 列出其中的文本、图片和 PDF 名字。点文本能看到正文。点图片和 PDF 时把内容交给对应查看器，而不是由压缩包自己解析。tar、gz、tgz 显示先不看，读文本的动作不会发生。
- [ ] AC4: 压缩包不在或内容打不开时，画面显示原因，最近列表不追加，上一份正文不留。超过 20MB 的压缩包不解析。有密码时说明先不看，不出现密码框。
- [ ] AC5: 名单出现后，这份 ZIP 才进入最近列表。影音能播之后才进入。失败不进。换文件后上一份名单或地址不留在画面状态里。成功打开的 PDF 仍然不进最近列表。

## Verification Method

- AC1: 单测读启用名单和加载函数。六个家族都能加载，没有加载函数指向关掉的家族。
- AC2: 构建后跑分包检查。依赖边界检查确认 Rust 侧没有压缩或影音解析库，压缩包读取文件不引用 PDF 查看器或 pdf.js。
- AC3: 用测试里生成的最小 ZIP 做名单和条目预览。文本断言正文。图片和 PDF 断言交出去的是字节，不是解析结果。tar、gz、tgz 断言文案，并断言没有去读内容。
- AC4: 单测让确认文件失败，断言原因、最近列表不变、上一份不在。再断言超大不解析，以及密码错误被说成先不看。
- AC5: 单测断言交出地址时最近列表不变，名单出现或能播之后才追加。晚到的成功不盖住下一份。PDF 成功不进最近列表的原测试仍然成立。换文件的状态里没有上一份名单。
