# 打开失败说清原因，只认最后一次打开

## 本次交付目标

在自己的 Mac 上，打开失败时要看到原来的原因，已经不在的文件不要装成打开成功，连续打开时只留下最后一次。这一段由模型自主确认验收和方案，没有逐项等人点头。收口前做了完整审查。审查发现清理缓存的时机不对，已经改完并重新测过。审查是在同一段上下文里做的，不是另一份干净上下文的复查。

## 已完成内容

- 本机返回的失败原因会原样显示，不再一律收成「打不开」。最近列表不因此多一条，上一份内容会清掉。
- 打开 jpg、png 这类普通图片之前，先确认这是一个还在的文件。文件不在，或路径是目录时，说明原因，不写入最近列表。
- 连续打开只留下最后一次的画面和最近列表。最近列表还没从磁盘读完时，打开先排队，不会用空列表盖掉磁盘上的记录。读失败时画面仍可打开，但不会把空列表写回去。
- HEIC 解码只写出一张新图。只有这次结果被采纳，才会清理缓存里的其他 png，并且不会去删缓存目录以外的文件。更早的解码即使后返回，也不会把更新的那张图删掉。
- 解码程序固定为 `/usr/bin/sips`，参数是数组，不经过外壳拼接。
- 点 Markdown 里的链接，包括点在链接文字上，当前窗口不会因此跳走。

## 关键变更 / 用户可感知变化

失败会说出原因。已经删掉的图片不会再出现在最近打开里。快速连开两个文件时，后返回的那次盖不住新的。

## 高层影响范围

改动在打开流程、HEIC 缓存清理和 Markdown 点击。启用名单仍然只有图片和文本。没有做 PDF、Office、压缩包和影音。没有重开上一段，也没有改它的归档。

验收 AC1 到 AC6 都有机器记录，结论是通过。记录在 `.ai/iterations/ITER-0002/evidence/`。前端 24 项、Rust 6 项都通过。审查时读过这两份输出。没有在真窗口里再连续点两个文件，HEIC 也没有在窗口里再打开一次。

## 已知剩余风险 / 延后事项

- 真窗口里没有再连续打开两个文件，也没有再打开一次 HEIC。单测钉住了验收里写的动作，不能当成已经在窗口里点过。这不卡后面的 PDF。
- 清理紧跟在画面状态提交之后。新图可能还没画出来，上一张缓存图就已经删了。要显示的那张会留下。若系统还要重读上一张，可能会闪一下。
- 被丢掉的 HEIC 如果更晚写完，会留下一张不再显示的缓存图。下次成功打开才会清掉。
- 浏览器拖放没有本机路径，缺文件这条不覆盖它。
- Markdown 链接点击被拦住，链接文字还在。中键没有另测。消毒后仍可能留下样式标签，样式不执行脚本。
- 最近列表写入失败时界面不提示。
- 依赖审计还有告警，没有强制升级。
- 本段是同一上下文的完整审查，不是独立复核。
- PDF、Office、压缩包和影音还在后面的路线里。
