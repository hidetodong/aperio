窗口壳、最近打开、图片和文本

ITER-0001 迭代交付（小版本） 收口 2026-09-29

本次交付目标

在自己的 Mac 上打开浮现，拖进或选中图片和文本就能看，最近打开过的文件会留下来。这一段由模型自主确认验收和方案，没有逐项等人点头。收口前做了完整审查，结论是可以通过，没有必须先改才能交付的问题。审查是在同一段上下文里做的。项目没有打开独立复核，所以这不是另一份干净上下文的复查。

已完成内容

  • 窗口可以点按钮打开文件，也可以把文件拖进来。看完能回到最近列表。
  • 最近列表同一路径只留一条，最新在前，最多 20 条。列表写在本机应用数据目录，重启后还在。文件已经不在时说明原因，并清掉上一份内容。
  • 图片支持 jpg、jpeg、png、gif、webp、svg、heic、heif。HEIC 和 HEIF 用系统自带的 sips 转成 PNG，页面拿不到原始字节。
  • Markdown 会排版并去掉脚本。HTML 放在不允许脚本的框架里。其余纯文本按原文显示。只有约定的那几种语言会高亮。
  • 启用名单只打开图片和文本。PDF、Office、压缩包和影音会显示不支持，也不会去加载对应查看器。
  • 同一时间只保留当前这一份文件。文本超过 2MB 会拒绝并说明原因。

关键变更 / 用户可感知变化

拖一张图或一份 Markdown 进来就能看。侧栏能点回最近开过的文件。还不支持的格式会直接说明，不会装出已经打开的样子。

高层影响范围

界面在 src/，读文本和 HEIC 解码在 src-tauri/。图片查看器和文本查看器分开加载，不打进主包。这一段不做 PDF、Office、压缩包、影音，也不做编辑、对外分发、付费或自动更新。

验证方式与结果摘要

验收 AC1 到 AC7 都有机器记录，结论是通过。记录在 .ai/iterations/ITER-0001/evidence/。审查时又重跑了前端测试和 Rust 测试。开发窗口里拖入过一张 PNG，能看到内容和同一条最近记录。HEIC 只在解码命令里用系统样例跑通，没有在窗口里再打开一次。

已知剩余风险 / 延后事项

  • HEIC 没有在窗口里再打开一次。
  • 冷启动到能接拖放没有用秒表量。空窗口时主进程大约 32MB，打开一张照片后大约 38MB。系统网页视图是另一个进程，没有合成成一个总账。80MB 不是这一段的通过线。
  • 依赖审计还有 3 条告警，没有强制升级。
  • Markdown 消毒后仍可能留下样式标签。样式改的是样子，不是执行脚本。
  • 最近列表写入失败时界面不提示。重启后以磁盘上的那份为准。
  • 本地资源协议开得比较宽，靠页面不执行脚本来兜。这是方案里已经接受的取舍。
  • PDF、Office、压缩包和影音还在后面的路线里，这一段没有做。
  • 收口之后的代码审查又看到三处：真窗口里，本机返回的失败原因会被收成「打不开」；已经删掉的普通图片仍会进最近列表；后返回的上一次打开可能盖掉新文件。归档里的验收记录保持收口当时的样子，不回头改。这三处交给下一段修。
